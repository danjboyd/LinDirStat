# WinDirStat Parity Checklist

This checklist tracks LinDirStat against the local WinDirStat reference source in `references/WinDirStat`.

Status values:

- `matched`: implemented and covered enough to rely on
- `partial`: present but not complete
- `deferred`: planned but not started
- `different`: intentionally different, with rationale

## Core Workflow

| Area | Status | Notes |
| --- | --- | --- |
| Directory scan | matched | Background scanner using `fstatat` with a pool of libdispatch workers (Preferences › Advanced, 1–16, default 4), hard links counted once, physical (`st_blocks`) and logical sizes, mtime and mode. WinDirStat's exclusions: mount points (another `st_dev`) and symbolic links are excluded by default (file links skipped, folder links shown as leaves; when followed, folder links are descended with cycle protection and file links count their target), hidden (dot) entries optionally. Filtering page: folder path patterns, file name patterns (glob or POSIX ERE, case-insensitive, anchored) and a minimum file size; an invalid pattern stops the scan with a message. Suspend/Resume and Stop (partial results). Multi-volume scans produce a "This Computer" root. |
| Size semantics | matched | Physical size by default; Treemap › Use Logical Size switches every pane. Directories contribute no bytes of their own. |
| Hard links | matched | WinDirStat's "Scan drives and display hardlink information" (Preferences › Advanced, default on, `LDHardLinks`): a file with several links in the scan is counted once under a `<Hardlinks>` pseudo-folder in its scan root, with WinDirStat's "Index ≡ 0xNN" sets (inode modulo 20) and an "Index 0x…" folder per file listing every link by path. Each link shows "⧉ <size>" in Physical Size and adds nothing to its folders; the references show "⫘ <size>". Clicking either cell (hand cursor) jumps to the other side; selecting a link frames its Index folder in the treemap, where the Index folders are leaves drawn in RGB(200,150,100) made lighter (`COLORFLAG_LIGHTER`). The pseudo-items are left out of the extension list, Largest/Duplicates/Search, CSV and every command. Refresh Selected and deletions keep the scan's hard-link table: a refreshed subtree does not count again a file whose other links are outside it, a remaining link takes over the bytes when the counted one goes, and `<Hardlinks>` is rebuilt. Off: links are counted once at the first link found, as before (WinDirStat counts every link when off). Different: logical sizes are de-duplicated too (WinDirStat only adjusts physical sizes); `<Hardlinks>` appears only when there are links (WinDirStat always adds it, with 20 empty sets); the option applies at the next scan instead of rescanning at once. |
| Directory tree pane | matched | WinDirStat's columns: Name, Subtree Percentage, Percentage and the optional Physical Size, Logical Size, Items, Files, Folders, Last Change, Attributes (R and H; the other letters have no Linux meaning) and Owner, chosen in Preferences › Folder List. Sortable headers, multiple selection, symbolic icons, depth-indented percentage bars, dimmed unreadable folders and mount points. Live while scanning: rows appear as directories are read, re-sorted twice a second, with WinDirStat's pacman (or "[N Read Jobs]") on folders still being read; a pacman whose folder made no progress for 750 ms stops and draws "zzz" (`LDScanClock`). The Percentage column shows the time spent ("[m:ss]") on the root and on every row whose folder is still being read, as WinDirStat's ShowTimeSpent does; the times live in two 16-bit stamps in `LDDirectoryNode`'s former padding, so no node grows. Name sorts folders before files (WinDirStat's item type order). The context menu starts with Expand/Collapse for rows with children. Depth colours and how many are used in turn are set in Preferences › Folder List (WinDirStat's FileTreeColor0–7 and FileTreeColorCount; defaults are GNOME's palette in WinDirStat's order). Automatically resize columns (Preferences › General, default on) fits the columns other than Name and the graph to their widest value after a scan. Different: Logical Size is off by default because two size columns do not fit beside the extension list at GNOME's metrics; AppKit has no default (bold) menu item, so Expand/Collapse is only placed first; automatic column sizing fits the numeric columns after a scan instead of widening Name on expand (Name already takes the free width). |
| File tabs | matched | All Files, Largest Files (top N by logical size, Preferences › Advanced, live while scanning), Duplicate Files (when "Scan for duplicate files" is on: found during the scan as in WinDirStat, with files bucketed by size as they are read and buckets of two or more hashed on a low-priority queue with SHA-512/128 of the first 4 KiB, 1 MiB and whole file; the tab says "(searching…)" and fills twice a second, hashing may go on after the scan, and Stop stops it. A tree loaded from CSV is hashed after loading) Search Results (after a search) and File Watcher (Tools › Start File Watcher). Different: tabs are on top, as GNOME places them. |
| File Watcher | matched | Tools › Start/Stop File Watcher shows or hides the tab, as WinDirStat's toggle does. WinDirStat's columns (Name, Time, Operation, Logical Size; newest first) and verbs (Created, Deleted, Modified, Renamed (Old), Renamed (New)); folder modifications are ignored, as in WinDirStat. `LDFileWatcher` with an inotify backend that watches the scan root (or each drive of "This Computer") recursively on its filesystem, follows renamed folders, watches new ones (listing what they already hold as created), turns moves in and out of the tree into Created and Deleted, and reports queue overflows and the watch limit in the status bar. Batched onto the main thread four times a second; repeated writes to one file collapse into one row per batch. Selecting a row selects the item at that path in the tree. Different: the list keeps the newest 10,000 rows; a new scan empties it and, while the watcher is on, watches the new tree when the scan finishes (WinDirStat stops watching). macOS: FSEvents backend still to come (unsupported until then). |
| Search | matched | Edit › Search… with WinDirStat's options (regular expression, case sensitive, whole phrase; `*` implies whole phrase), names of files only, capped at 10,000 largest. Different: regular expressions are POSIX extended, not ECMAScript. |
| Extension/type pane | matched | Rank-based WinDirStat colours with cushioned swatches, descriptions from shared-mime-info, bytes, % bytes, files, sortable headers; selecting an extension highlights its files in the treemap. Options › Show File Types hides it. |
| Treemap pane | matched | Port of `CTreeMap`, pixel-identical to the oracle. Selection frame, extension highlighting, zoom in/out/reset, Select Parent and Reselect Child, context menu, hover path in the status bar. Preferences › Treemap sets style, grid, grid colour (black), highlight colour (white, the selection frame), brightness, cushion shading, height, scale factor and light source, with WinDirStat's live preview of its demo tree (`LDTreemapPreview`). Options › Show Treemap hides it. |
| Free space and unknown | matched | Options › Show Free Space (F6) and Show Unknown (F7), off by default and persisted (`ShowFreeSpace`, `ShowUnknown`): `<Free Space>` and `<Unknown>` pseudo-files under each volume root (a scan root that is the root of a filesystem, or each volume under "This Computer"). Free space is `statvfs` `f_bavail × f_frsize`, unknown is the used space (`f_blocks × f_frsize` − free) the scan did not find, never below 0; both are physical sizes only, count in totals and percentages, and are recomputed after every scan and refresh. Toggling adds or removes them without rescanning. Treemap colours are WinDirStat's (grey, darker; yellow, lighter) with `CTreeMap`'s colour flags, covered by the parity gate. They are not files: no extension, Largest Files, Duplicates, Search, command or custom cleanup uses them. CSV writes them with type bits `0x10`/`0x20` and reads them back. |
| Status/progress | matched | Scans of volumes (a mount point, or "This Computer") show a percentage bar in the status bar measured against the volumes' used space (`statvfs`) and "NN%" before the window title, with "(Suspended)" while suspended; other scans, and scans that may leave the volume (mount points or symlinks followed), show the spinner and "Scanning" (`LDScanProgress`). Live counts while scanning, hovered or selected path, the size of the whole selection ("Physical Size: …"), memory use. |
| Window chrome | matched | GNOME header bar with Select Target, Refresh, Suspend/Resume, Stop, Search, Move to Trash, Select Parent, Zoom Out, Zoom In; the primary menu has File, Edit, Clean Up, Treemap, Options and Help. Options › Show Toolbar (F10), Large Toolbar Icons and Show Status Bar (F11) are remembered. Ctrl+F1–F4 show the file tabs; Tab and Shift+Tab walk the visible file tabs and the extension list (WinDirStat's CycleTab). Help › LinDirStat Help (F1) opens the project page and Report a Bug… its new-issue page. Drawn entirely by the Adwaita GNUstep theme, light or dark. Different: the Adwaita header bar draws its icons at 16 px in either toolbar size. |
| Folder/drive selection | matched | Select Target offers all local drives, individual drives (with total, free and a usage bar from `statvfs`; pseudo, network and FUSE filesystems left out) or a folder with a history, plus the duplicates option. |
| CSV | matched | File › Save/Load Results To CSV and Save Duplicates To CSV in WinDirStat's formats, including `<Free Space>`/`<Unknown>` rows; WinDirStat's own CSVs load too. A "This Computer" scan is written as WinDirStat's MyComputer row with its roots as drives, and loads back the same way. As in WinDirStat, `<Hardlinks>` is not written and the hard-link de-duplication is undone (every link with the file's sizes, every folder with all the links below it) and Index is the inode (looked up with `lstat` when saving). Loading counts files with the same non-zero Index once and rebuilds `<Hardlinks>`; files with Index 0 (older LinDirStat CSVs) are taken as written. Different: embedded quotes are doubled. |
| Command line | matched | `LinDirStat [folder…]` scans the folders (several under "This Computer"; folders that do not exist are ignored). `--savetocsv FILE folder…` and `--savedupestocsv FILE folder…` scan, save the results or duplicates (the latter turns duplicate detection on for that run) and exit 0, or 1 on failure, without a window or a display; both can be given in one run. `--loadfromcsv FILE` opens the app showing a saved CSV. Flags are case-insensitive and also accept WinDirStat's `/savetocsv` and `-savetocsv` spellings. Different: with a save flag and no folder, LinDirStat reports "No folder to scan" and exits 1 instead of showing the folder dialog. |
| Preferences | matched | WinDirStat's Options pages as a GNOME Preferences window: General, Filtering, Folder List, Treemap, Cleanups, Prompts, Advanced, including the treemap colour pickers and preview and the subtree percentage colours. Windows-only settings are left out; dark mode follows GNOME's style instead of an app setting. |

## File Actions

| Area | Status | Notes |
| --- | --- | --- |
| Open | matched | `xdg-open` (`open` on macOS) for each selected item; Enter. |
| Open With | matched | WinDirStat's "Windows Explorer Menu" submenu, at the end of the Clean Up and file list menus: the applications that open every selected item, the default first. `LDOpenWith`: desktop entries from `$XDG_DATA_HOME` and `$XDG_DATA_DIRS`, the user's and system's `mimeapps.list` (desktop-specific lists first; default, added and removed associations), shared-mime-info aliases and subclasses (a C file also offers text editors); started through the `Exec` line with `%f %F %u %U %i %c %k` expanded and exact path bytes, in a terminal for `Terminal=true`. macOS: NSWorkspace backend still to come (empty until then). |
| Show in Files | matched | `org.freedesktop.FileManager1.ShowItems` over D-Bus (gdbus or dbus-send), falling back to opening the containing folder. WinDirStat's "Select in Explorer". |
| Open Terminal Here | matched | WinDirStat's Command Prompt/PowerShell Here: `$TERMINAL`, GNOME Console, GNOME Terminal, Ptyxis, Konsole, Xfce Terminal, `x-terminal-emulator` or xterm, in each selected folder (a file's parent). |
| Properties | different | An in-app panel (path, type, sizes, contents, permissions, owner, group, links, inode, times) instead of the shell's dialog. |
| Copy Path | matched | Every selected path, one per line. |
| Move to trash | matched | freedesktop.org Trash 1.0: the home trash, or `$topdir/.Trash/$uid` / `$topdir/.Trash-$uid` on other filesystems; never copies across filesystems, never overwrites. Del. |
| Delete permanently | matched | Shift+Del; never follows symbolic links or enters other filesystems; reports what it could not remove. |
| Delete warning | matched | WinDirStat's warning lists every path, defaults to Cancel and has "Do not show this message again" (Preferences › Prompts restores it). |
| Empty Folder, Move To, Empty Trash | matched | Empty Folder deletes a folder's contents permanently; Move To renames, or uses `mv` across filesystems, never replacing; Empty Trash empties the home and per-volume trashes. Its menu title shows "(N Items, X)", measured in the background (at most every 10 s, capped at 20,000 entries, "X+" when capped) as WinDirStat's does. |
| Refresh | matched | After any change on disk the affected items are rescanned in place or removed, totals and order updated upward, with selection and zoom kept (WinDirStat's refresh engine); a trash folder inside the tree is refreshed after trashing. Refresh Selected (F5), Refresh All (Shift+F5). |
| Custom cleanups | matched | Ten slots (Ctrl+0–9) with WinDirStat's fields and rules: `/bin/sh -c`, `%p`, `%n`, `%sp`, `%sn`, works-for kinds, recursion (children first), confirmation, run in a terminal, wait, refresh policy. Different: WinDirStat pastes paths unquoted; Linux names can contain quotes and `$(…)`, so placeholders become shell parameters with the exact paths passed as arguments. |
| Compute Hash | matched | MD5, SHA-1, SHA-256, SHA-384 and SHA-512 of one file. |
| Windows-only cleanups | different | Compression, sparse files, hibernation, Disk Cleanup, and shadow copies have no Linux equivalent and are left out; the Explorer menu is Open With. |

## Automated Visual Parity

Run:

```sh
./scripts/windirstat-parity-gate.sh
```

The gate renders each fixture in `Tests/Fixtures/windirstat-parity/trees.json` at three viewport sizes with the production renderer (`Tools/windirstat-parity-exporter --ppm`, which calls `LDTreemap` and the rank-based palette) and with an independent Python port of WinDirStat's `CTreeMap` (`references/WinDirStat/windirstat/Controls/TreeMap.cpp`). It is strict by default: any leaf rectangle difference, any channel drift above 2, or under 99.9% exact pixels fails. Current status: all fixtures match exactly.

Output is written to `dist/validation/windirstat-parity`, including both images, a diff image, rectangle JSON and `summary.json`.

## Full-Window GUI Parity

Run:

```sh
./scripts/gui-parity-gate.sh
```

The gate starts its own Xvfb display (the first free one from `:90`, or `GUI_PARITY_DISPLAY`), generates the fixture in `Tests/Fixtures/gui-parity/tree.json` (97 files with fixed sizes, contents and mtimes, two duplicate groups) under `dist/validation/gui-parity/work`, and runs the built app on it with a private `GNUSTEP_HOME` (Adwaita theme, fixed 1280x820 window, duplicate detection on) in the light and dark styles (a private GSettings keyfile). It drives the app with `xdotool` through: completed scan, extension selected, tree selection framed in the treemap, Largest Files, Duplicate Files, the file tree's context menu and Preferences. The scanning state is skipped because its frames depend on timing.

Each state is checked from the geometry the app reports (`LINDIRSTAT_DUMP_LAYOUT=path` makes the app rewrite a JSON description of its windows, views, table columns and header title widths, tabs, treemap cells and state whenever it changes; without the variable nothing runs) and from a screenshot:

- WinDirStat's composition: file view left at 60% of the width (WinDirStat: 72%, see `AppController -applyDefaultSplitPositions`), extension list right, treemap full width below at 50% of the height;
- file tree, extension list, Largest Files and Duplicate Files columns present and in WinDirStat's order; file tabs and the context menu's commands in order; WinDirStat's menus in the main menu and the menu reachable; toolbar commands; status bar at the bottom;
- no overlapping sibling views (scroll views' overlay scrollers excepted), no clipped column titles, every title visible without scrolling sideways, panes inside the window;
- treemap density (leaf count within the fixture's range and equal to the renderer's);
- the screenshot is not blank, the Adwaita header bar and list background match the style;
- the treemap on screen equals `Tools/windirstat-parity-exporter --path` (the Phase 11 renderer) for the same tree and size, rectangles exactly and pixels with the Phase 11 thresholds, and that renderer equals the WinDirStat oracle for the fixture; selection and extension highlight frames are drawn on the right cells.

It is strict by default; `GUI_PARITY_STRICT=0` records without failing, and `GUI_PARITY_STYLES=light` runs one style. Screenshots, per-state layout JSON, treemap crops and diffs and `summary.json` (checks plus non-failing `findings`) are written to `dist/validation/gui-parity`. The gate fails if `~/GNUstep/Defaults` changes during the run (unless another LinDirStat instance was running, which is reported instead).

Current finding (reported, not failed): GNUstep's `NSSplitView -setPosition:ofDividerAtIndex:` takes the position as the divider's centre, so with the 1px thin divider every pane sits on half pixels (`topSplit`, `fileTabs`, `extensionPane`, `treemap`). The treemap keeps its cells on whole window pixels and blits them without interpolation (`LDTreemapView -treemapArea`); before that the screen differed from the renderer (blended rows, the shadow line over the last row).

`./scripts/gui-parity-correlation.sh` still pairs a single screenshot with the headless metrics.
